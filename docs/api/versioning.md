# API versioning

All services live in versioned protobuf packages
(`vectra.<service>.v1`) under `contracts/proto/vectra/`. The rules:

1. **Within v1, changes are additive.** New fields get new numbers; field
   numbers and names are never reused or renumbered; removed fields are
   `reserved`. Old clients keep working, and new fields default to the old
   behavior (for example `sold_before_epoch_day = 0` means no bound, and
   `valuation_epoch_day = 0` means today).
2. **A semantic change is a new major version** (`v2` package), served next
   to `v1` until every client has moved.
3. **One source of truth.** C++ stubs are generated by CMake
   (`engine/cmake/GrpcProtoGen.cmake`) and Python stubs by
   `scripts/gen_proto.sh` into `build/gen/python`. Generated code is never
   committed.
4. **Configuration is a contract too.** `engine/configs/*.textproto` are
   parsed against `config.proto` by the engine, the gateway and the data
   pipelines alike, so a schema change reaches all three in one PR.

Changes in v1 since the design baseline:

| Change | Field |
|---|---|
| Valuation date for backtests and reproducible prices | `PredictPriceRequest.valuation_epoch_day` (5) |
| Sale-date bound pushed into the search | `SearchRequest.sold_before_epoch_day` (8) |
